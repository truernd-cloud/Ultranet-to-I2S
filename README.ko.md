# Ultranet-to-I2S (한국어)

[English README](README.md)

Raspberry Pi Pico(RP2040)로 Behringer Ultranet 두 스트림(16채널)을 모두 디코딩하고, 16채널을 스테레오 2채널로 믹스해 I2S 출력 하나로 내보내는 펌웨어입니다. 믹스는 동작 중에 MIDI로 조작할 수 있습니다. (버전 2.1)

> 원본(버전 1.2)은 스트림 하나(8채널)만 받아 I2S 4개와 PWM 8개로 채널을 그대로 내보냈습니다. 버전 2.x에서 달라진 점은 아래 [버전 1.2와의 차이](#버전-12와의-차이)에 정리했습니다.

## 개요

Raspberry Pi Pico에는 이 작업에 딱 맞는 기능이 두 가지 있습니다.

- **PIO 모듈**: 들어오는 Ultranet 스트림 두 개를 PIO 상태 머신 두 개가 각각 오디오 8채널로 디코딩합니다. 또 다른 PIO 상태 머신은 믹스 결과를 I2S로 출력합니다. I2S 출력은 PCM5102A 같은 저가 DAC 모듈에 바로 연결할 수 있습니다.
- **듀얼 코어**: 코어0은 Ultranet 샘플을 배열에 채우고, 코어1은 그 배열을 읽어 믹스한 뒤 I2S로 내보냅니다. Ultranet 입력은 송신 장비의 클럭을, I2S 출력은 Pico의 클럭을 따릅니다. 두 코어가 독립적으로 동작하므로 두 클럭의 작은 차이가 자연스럽게 흡수됩니다.

클럭 차이는 샘플을 한 번 더 출력하거나 하나 건너뛰는 방식으로 흡수됩니다. 기본 설정에서는 약 38ms마다 1샘플 정도입니다. 인접 샘플의 크기가 거의 같아서 보통은 들리지 않습니다.

## 동작 원리

| 항목 | 값 |
|---|---|
| 입력 | Ultranet 스트림 2개 (채널 1-8, 9-16), 동시 수신 |
| Ultranet 비트 레이트 | 스트림마다 12.288MHz (32비트 x 8채널 x 48kHz) |
| 바이페이즈 선로 클럭 | 24.576MHz |
| 시스템 클럭 (기본값) | 196.5MHz (선로 클럭의 약 8배로 샘플링) |
| 대안 시스템 클럭 | 172MHz (약 7배로 샘플링) |
| 오디오 샘플 | 22비트 (필드는 24비트, 하위 2비트는 사용하지 않음) |
| 믹스 | 16채널 → 스테레오 2채널. 채널별 레벨(dB)과 팬 설정 |
| MIDI 입력 | UART1, 31250 baud. CC7(볼륨), CC10(팬)으로 채널별 믹스 조작 |
| I2S 출력 | 스테레오 1개, 약 48kHz, 32비트 슬롯 |
| MCLK | 약 12.28MHz (256 x fs) |

클럭을 바꾸려면 다음 세 곳을 함께 수정해야 합니다.

- `ultranet.h`: `CLOCKSPEED` (196500 또는 172000), `AUDIV` (8 또는 7)
- `ultranet.pio`: `.define cy` (8 또는 7)

### PIO 상태 머신 배치

| PIO | SM | 용도 |
|---|---|---|
| pio0 | SM0 | Ultranet 하위 스트림 수신 (GP0, 채널 1-8) |
| pio0 | SM1 | Ultranet 상위 스트림 수신 (GP1, 채널 9-16) |
| pio0 | SM2 | WS2812 상태 LED |
| pio0 | SM3 | I2S MCLK |
| pio1 | SM0 | I2S 출력 |

두 Ultranet 상태 머신은 PIO 메모리에 적재한 같은 프로그램을 함께 씁니다.

### 소스 파일 구성

| 파일 | 내용 |
|---|---|
| `ultranet.h` | 공용 헤더: 핀 배치, 클럭, 옵션 스위치, LED 색상 정의 |
| `ultranet.c` | 코어0: 초기화, 두 스트림의 프레임 동기 및 샘플 디코딩, 상태 LED |
| `core1.c` | 코어1: **믹스 테이블**, 16채널 믹스, MIDI 입력 처리, I2S/MCLK 출력 |
| `ultranet.pio` | PIO 프로그램: Ultranet 수신기, MCLK, I2S 송신기, WS2812 LED 드라이버 |

## 핀 배치

| GPIO | 기능 |
|---|---|
| GP0 | Ultranet 하위 스트림(채널 1-8) 입력 |
| GP1 | Ultranet 상위 스트림(채널 9-16) 입력 |
| GP2 / GP3 / GP4 | I2S 출력: DATA / BCLK / LRCLK |
| GP5 | MIDI 입력 (UART1 RX) |
| GP16 | WS2812 상태 LED |
| GP24 | I2S MCLK 출력 |

> **주의:** 공식 Raspberry Pi Pico 보드에서는 GP24(VBUS 감지)가 내부에 연결되어 있어 핀 헤더로 나오지 않습니다. 이 핀 배치는 GP16에 WS2812 LED가 있는 소형 중국산 RP2040 보드를 기준으로 합니다. 공식 Pico를 쓴다면 `ultranet.h`에서 `MCLK_PIN`을 사용 가능한 핀으로 바꾸거나, `MCLK` 정의를 주석 처리해 MCLK를 끄세요. PCM5102A는 SCK 핀을 GND에 연결하면 MCLK 없이 BCLK만으로 동작합니다.

## 믹스 설정

믹스는 `core1.c`의 `mix_table[]`에서 채널별로 설정합니다. 값을 고친 뒤 다시 빌드하고 펌웨어를 올리면 적용됩니다.

```c
static const mix_channel_t mix_table[UNET_CHANNELS] =
{
    //  gain_db   pan               channel
    { -12.0f,   0.0f },         //  1
    { -12.0f,  -1.0f },         //  2  완전히 왼쪽
    {   MUTE,   0.0f },         //  3  끔
    ...
};
```

| 항목 | 범위 | 설명 |
|---|---|---|
| `gain_db` | `MUTE`, 또는 +6.0 이하 | 채널 레벨(dB). 0.0 = 원래 크기. `MUTE` = 끔 |
| `pan` | -1.0 ~ +1.0 | -1.0 = 완전히 왼쪽, 0.0 = 가운데, +1.0 = 완전히 오른쪽 |

- **기본값**: 16채널 모두 -12dB, 가운데입니다.
- **팬 방식 (밸런스)**: 가운데 채널은 양쪽에 원래 레벨로 들어갑니다. 한쪽으로 팬하면 반대쪽 레벨만 줄어듭니다. 예를 들어 `pan = +0.5`이면 왼쪽은 절반(-6dB), 오른쪽은 그대로입니다.
- **클리핑**: 믹스 합이 풀스케일을 넘으면 최댓값에서 잘립니다. 여러 채널이 동시에 큰 소리를 내면 클리핑될 수 있으니 레벨에 여유를 두세요.
- **정밀도**: 믹스 계산은 22비트 샘플과 고정소수점 게인(512 = 원래 크기)으로 합니다. 게인이 작을수록 오차가 커집니다. -40dB는 약 0.2dB, -50dB는 약 2dB 오차가 나고, 약 -54dB보다 작은 값은 -54dB 또는 무음으로 처리됩니다. 채널을 끄려면 `MUTE`를 쓰세요.

## MIDI 입력

MIDI 컨트롤 체인지(CC) 메시지로 동작 중에 채널별 볼륨과 팬을 바꿀 수 있습니다. **MIDI 채널 번호가 믹서 채널 번호**입니다. MIDI 채널 1~16이 믹서 채널 1~16에 대응합니다.

| 메시지 | 값 | 동작 |
|---|---|---|
| CC 7 (볼륨) | 0 ~ 127 | 0 = 끔, 127 = 원래 크기(0dB). 곡선은 (값/127)²로, General MIDI와 같습니다. 예: 100 ≒ -4dB, 64 ≒ -12dB |
| CC 10 (팬) | 0 ~ 127 | 0 = 완전히 왼쪽, 64 = 가운데, 127 = 완전히 오른쪽 |

- 다른 메시지(노트, 프로그램 체인지, 시스템 익스클루시브, 클럭 등)는 무시합니다. 러닝 스테이터스를 지원합니다.
- MIDI로 바꾼 값은 `mix_table[]`의 값을 대신하며, 전원을 다시 켜면 `mix_table[]` 값으로 돌아갑니다.
- MIDI로 올릴 수 있는 최대 볼륨은 0dB입니다. `mix_table[]`에서는 +6dB까지 설정할 수 있습니다.
- 값은 다음 샘플부터 바로 적용됩니다. 페이더를 빠르게 움직이면 작은 계단 잡음(지퍼 노이즈)이 들릴 수 있습니다.

**하드웨어**: MIDI 규격상 입력은 광절연해야 합니다. 일반적인 MIDI IN 회로(DIN 5핀 → 220Ω → 6N138 또는 H11L1 같은 포토커플러)의 출력을 3.3V로 풀업해 GP5에 연결하세요. 포토커플러 출력을 5V로 풀업하면 안 됩니다. 컨트롤러가 3.3V 로직의 UART(TTL MIDI)를 출력한다면 GP5에 바로 연결해도 됩니다.

MIDI를 쓰지 않으려면 `ultranet.h`의 `#define MIDI`를 주석 처리하세요. 핀과 UART는 `MIDI_UART`, `MIDI_RX_PIN`에서 바꿀 수 있습니다. UART1 RX로 쓸 수 있는 핀은 GP5, GP9, GP21, GP25입니다.

## 상태 LED (WS2812)

| 색 | 의미 |
|---|---|
| 파랑 | 하위 스트림(채널 1-8) 수신 중 |
| 초록 | 상위 스트림(채널 9-16) 수신 중 |
| 파랑 + 초록 (청록색) | 두 스트림 모두 수신 중 |
| 빨강 | 프레임 동기 오류가 한 번 이상 발생. 재부팅 전까지 켜져 있음 |

스트림 표시는 약 200ms마다 갱신되므로, 스트림이 끊기면 해당 색이 곧 꺼집니다. 한쪽 스트림만 연결해도 그 스트림은 정상 동작하고, 연결되지 않은 스트림의 채널은 무음으로 믹스됩니다.

일반 Pico 보드의 기본 LED(GP25)를 쓰려면 `ultranet.h`의 `#define PICO_LED 25` 주석을 해제하세요. 현재 코드는 `WS2812` 정의가 있어야 컴파일되므로 `WS2812`는 켜 둔 채로 사용해야 합니다([코드 리뷰](CODE_REVIEW.ko.md) 4번).

## 하드웨어

Ultranet 케이블의 차동 신호를 Pico가 받을 수 있는 단일 종단 TTL 신호로 바꾸려면 라인 리시버 IC가 필요합니다. 두 스트림을 모두 받으려면 두 쌍을 모두 리시버에 연결해 GP0과 GP1로 넣어야 합니다. 제작자의 시제품은 MC3486(4채널 라인 리시버)과 5V 레귤레이터를 사용합니다.

## 빌드

개발 환경은 Raspberry Pi Pico C/C++ SDK와 Visual Studio Code(Raspberry Pi Pico 확장)입니다. `CMakeLists.txt`는 SDK 2.1.0, 툴체인 13_3_Rel1을 지정합니다.

VS Code 확장을 쓰면 프로젝트를 열고 **Compile Project**를 실행하면 됩니다. 명령줄에서 빌드하려면 다음과 같이 합니다.

```sh
export PICO_SDK_PATH=/path/to/pico-sdk
mkdir build && cd build        # 빌드 디렉터리 이름은 반드시 "build"여야 합니다
cmake ..
make
```

빌드가 끝나면 `build/Ultranet.uf2`가 생깁니다. Pico의 BOOTSEL 버튼을 누른 채 USB에 연결한 뒤, 나타나는 드라이브에 이 파일을 복사하면 됩니다.

> **알려진 빌드 제약**
> - `ultranet.h`가 `build/ultranet.pio.h`를 직접 include하므로, 빌드 디렉터리가 소스 폴더 바로 아래의 `build`여야 합니다.
> - `REBUILD_BINARY_INFO` 타깃이 SDK 안의 파일을 `touch`하므로 SDK 폴더에 쓰기 권한이 있어야 합니다.

## 버전 1.2와의 차이

| 항목 | 1.2 | 2.1 |
|---|---|---|
| 입력 | 스트림 1개 (부팅 시 셀렉터로 선택) | 스트림 2개 동시 수신 (16채널) |
| 출력 | I2S 스테레오 4개 + PWM 모노 8개, 채널을 그대로 출력 | I2S 스테레오 1개, 16채널 믹스 |
| PWM 출력 | 있음 | 없음 |
| 셀렉터 스위치 (GP11~13) | 스트림과 채널 배치 선택 | 사용하지 않음 |
| MCLK 상태 머신 | pio0 SM1 | pio0 SM3 |
| LED | 파랑 = 수신, 빨강 = 오류 | 파랑 = 1-8, 초록 = 9-16, 빨강 = 오류 |
| MIDI | 없음 | UART MIDI 입력(GP5)으로 볼륨/팬 조작 |
| 빌드 | Linux에서 파일 이름 대소문자 문제로 실패 | 수정됨 |

## 오버클럭 관련

기본 설정은 RP2040을 196.5MHz로 오버클럭합니다. 제작자는 여러 중국산 호환 보드에서 문제없이 동작하는 것을 확인했습니다. 동작이 불안정하면 172MHz 설정(위 "동작 원리" 참고)을 시도해 보세요.
